# emotion_diary
# 음성 기반 AI 감정 일기 및 음악 추천 시스템

말하는 것만으로 하루의 감정을 기록하고, 그 감정에 어울리는 음악을 추천받는 서비스입니다.

**서비스 바로가기**: https://emotion-diary-c111208-e3d0f.web.app

## 소개

바쁜 일상 속에서 감정을 글로 기록하는 건 번거롭고 부담스럽습니다. 이 프로젝트는 사용자가 하루 중 언제든 짧게 음성으로 기분이나 있었던 일을 남기면, AI가 하루치 기록을 종합해 감정을 분석하고 그에 어울리는 노래를 추천해주는 서비스입니다.

## 주요 기능

- 음성 녹음 및 자동 텍스트 변환 (Whisper)
- 목소리 톤 감정 분석 (wav2vec 2.0 미세조정 모델, 분석 시 Claude에 참고 정보로 전달)
- 하루치 기록을 종합한 감정 분석 및 조언 생성 (Claude)
- 감정에 어울리는 노래 추천 및 실제 존재 여부 검증 (iTunes Search API)
- 검증된 곡의 유튜브 링크 자동 연결 (YouTube Data API)
- 월 단위 중복 추천 방지
- 하루 1회 분석 제한 및 재조회 기능
- 사용자별 자동 분석 시각 설정 및 스케줄링
- 회원가입 및 로그인 (토큰 기반 인증)

## 기술 스택

**Backend**
- Python, FastAPI
- Supabase (PostgreSQL, Auth)
- APScheduler

**Frontend**
- Flutter (Web)

## 목소리 톤 분석 (wav2vec 2.0 미세조정)

글의 내용만으로는 알 수 없는 감정 신호를 보완하기 위해, 녹음된 음성의 톤에서 감정을 분류하는 모델을 직접 학습해 서버에 연동했습니다.

### 동작 흐름
1. 앱에서 녹음 → 서버로 업로드
2. Whisper가 음성을 텍스트로 변환
3. 서버가 같은 음성을 16kHz로 변환한 뒤 6초 단위로 나눠 wav2vec 모델로 5감정(angry, anxious, happy, neutral, sad) 확률을 계산하고 평균
4. 확률을 DB(`diary_entries.voice_tone`)에 저장
5. 설정한 분석 시각에 Claude가 글과 톤 결과를 함께 참고해 하루 감정·요약·조언·추천곡 생성

### 데이터
- AI Hub '감정 분류를 위한 대화 음성 데이터셋' (5차년도, 5차년도_2차)
- 5명 중 3표 이상 일치한 문장만 사용 (다수결 라벨)
- 5분류: angry(분노+혐오), anxious(공포), happy, neutral, sad / 놀람 제외
- 감정별 1,000개씩 총 5,000개 → train 3,500 / val 500 / test 1,000 (감정별 test 200개)
- 모든 모델을 같은 test 1,000개로 평가 (macro-F1, 혼동 행렬, 부트스트랩 95% 구간)

### 모델과 결과 (test 1,000개)
| 모델 | 설정 | 학습 시간 | 5분류 macro-F1 | 3분류 macro-F1 |
|---|---|---|---|---|
| 기준선: MFCC(80차원) + RBF SVM | - | - | 0.523 | 약 0.67 |
| wav2vec2-xls-r-300m v1 | lr 5e-5, 6 epoch | 약 28분 | 0.541 | 0.764 |
| **wav2vec2-xls-r-300m v2 (서버 사용)** | lr 3e-5, 12 epoch | 1시간 49분 (Colab T4) | **0.658** | **0.796** |
| 텍스트 KcELECTRA-base | lr 3e-5, 5 epoch | 약 100초 | 0.796* | 0.770* |

\* 11/12 첫 학습에서는 0.780 / 0.761이었고, 11/16 재학습한 결과(융합 실험에 사용)가 0.796 / 0.770입니다. 같은 설정에서도 실행마다 약 0.02 차이가 났습니다.

- 3분류는 good(happy) / flat(neutral) / bad(angry·anxious·sad)로 묶어 계산했습니다.
- v1→v2에서 학습률과 epoch를 동시에 바꿨기 때문에 어느 쪽의 효과인지는 분리하지 못했습니다. 다만 슬픔→불안 오분류가 줄었고 슬픔 재현율이 0.19에서 0.69로 올랐습니다.
- v2 감정별 F1: angry 0.52, anxious 0.65, happy 0.76, neutral 0.73, sad 0.63
- v2 검증 macro-F1은 epoch 1의 0.165에서 epoch 12의 0.653까지 오르는 추세였고 12 epoch 끝에서도 오르고 있어, 더 학습하면 개선될 여지가 있습니다.

### 텍스트 + 음성 융합 실험
| 방법 | 5분류 macro-F1 (95% 구간) | 3분류 macro-F1 | 중립 재현율 |
|---|---|---|---|
| 텍스트만 | 0.796 (0.773~0.818) | 0.770 | 0.54 |
| 음성만 | 0.658 (0.628~0.686) | 0.796 | 0.72 |
| 단순 평균 (0.5) | 0.842 (0.819~0.863) | 0.827 | 0.70 |
| 학습형 융합 (로지스틱) | **0.872 (0.850~0.890)** | **0.863** | 0.74 |

- 융합 모델은 검증 세트(500개)의 확률로만 학습하고 test 세트로만 평가했습니다.
- 텍스트·음성 단독보다 융합이 높았고, 구간도 겹치지 않았습니다. 단순 평균과 학습형 융합의 차이는 구간이 일부 겹쳐 단정하지 않습니다.
- 텍스트는 중립을 약하게 잡고(행복·분노로 오분류), 음성은 중립을 잘 잡는다는 점이 융합의 근거였습니다.

학습형 융합 혼동 행렬 (행=실제, 열=예측, 순서: angry anxious happy neutral sad)
```
[[185   1   1   7   6]
 [  0 193   0   3   4]
 [  2   1 172  22   3]
 [ 16   8  17 149  10]
 [  9   5   2  10 174]]
```

### 본인 녹음 시험 (학습에 쓰지 않은 데이터)
같은 문장 3개를 밝게/덤덤하게/가라앉게 말해 녹음한 9개로 확인했습니다.
- 3분류 기준 8/9 정답 (덤덤: 3/3, 밝음: 2/3, 가라앉음: 3/3)
- 가라앉은 톤은 "부정적"으로는 맞혔지만 불안·분노·슬픔 사이 세부 분류는 불안정했습니다.

### 한계
- 본인 녹음 시험은 표본 9개, 연기 녹음, 단일 화자라 참고 수준입니다.
- 화자 번호가 없어 같은 화자가 학습과 시험에 섞였을 수 있고, 비슷한 상황의 문장이 섞여 텍스트 점수가 낙관적일 수 있습니다.
- 같은 설정으로 다시 학습하면 점수가 약 0.02 달라질 수 있습니다 (텍스트 모델 재학습 결과).
- 융합 실험은 KcELECTRA 기준이며, 앱에서는 글 분석을 Claude가 담당합니다. Claude와 융합했을 때의 효과는 검증하지 않았습니다.
- 서버는 GPU 없이 CPU로 추론합니다.

### 모델 파일

## 트러블슈팅

### 1. AI 노래 추천 할루시네이션 문제
Claude가 존재하지 않는 가수-곡 조합을 추천하는 문제를 발견했습니다. Spotify, YouTube Music, MusicBrainz, Apple Music API 등 여러 대안을 비교 검토한 끝에, 무료이며 인증이 필요 없는 iTunes Search API로 곡의 실제 존재 여부를 검증하고, 실패 시 자동으로 재추천을 요청하는 로직을 구현했습니다.

### 2. 시간대 처리
국제표준시(UTC) 기준으로 데이터를 저장했을 때, 한국 사용자의 실제 하루 경계와 시스템이 인식하는 하루 경계가 어긋나는 문제를 발견했습니다. 한국 사용자만을 대상으로 하는 서비스라는 점을 고려해, 한국 시간(KST)을 직접 저장하는 방식으로 데이터베이스 스키마를 재설계했습니다.

### 3. Flutter Web 환경에서의 파일 업로드
`MultipartFile.fromPath`가 브라우저 환경(`dart:io` 미지원)에서 동작하지 않는 문제를 발견했습니다. 녹음된 오디오의 blob URL에서 바이트 데이터를 직접 읽어 `MultipartFile.fromBytes`로 전송하도록 수정해 해결했습니다.

### 4. 인증 방식 개선
초기에는 FastAPI의 기본 `Header` 방식으로 토큰을 받았으나, API 테스트 도구에서 파일 업로드와 커스텀 헤더를 함께 사용할 경우 인증 정보가 누락되는 문제를 발견했습니다. FastAPI가 공식 지원하는 `HTTPBearer` 방식으로 전환해 근본적으로 해결했습니다.

### 5. 모델 정밀도(float16) 타입 오류
학습한 모델이 float16으로 저장돼 있어, CPU 서버에서 float32 입력과 타입이 맞지 않는 오류가 발생했습니다. 모델을 불러올 때 `torch_dtype=torch.float32`로 지정해 해결했습니다.
